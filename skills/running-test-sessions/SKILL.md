# 执行测试会话

Session（测试会话）服从任务和证据，不服从脚本惯性。

## 从测试产物开始

按 `heuristic-testing` 定位项目 TCO 与当前 Spec 测试文档。执行前读取当前测试轮次、charter ID 或测试 ID、访问与安全边界、需要获得和保留的证据。没有当前 Spec 时，不创建测试包；在对话中完成获准的小修复验证。未知项明确为未知，不补写成事实。

## 执行

1. 核对本轮要执行与明确排除的 ID、起始风险、环境、执行人、时间、数据、oracle 和结束／转向信号。
2. 按访问权行动：
   - 无环境访问权：准备 probe、数据、操作、观察位置和 oracle，指导获授权的测试人员执行，只把其返回的原始观察记为结果；
   - 有明确授权和访问权：直接执行，保留命令或操作、环境版本、输入、时间、账号／权限、前置状态和原始结果。
3. 先运行最便宜、最能区分当前风险的 probe。计划、待执行或指导步骤保持未执行状态，不写成结果。
4. 分开记录原始观察与解释。每条结果和 finding 都引用实际执行的测试 ID 或 charter ID；重要 finding 保留复现所需的状态、数据、顺序、负载、环境和证据。
5. 意外若信息价值更高且仍在权限与安全边界内，跟进并记录分支；价值较低则停放，越界则停止。新 finding 可以新增候选测试点或产品风险并分配新 ID；保留既有执行证据，若后续证据改变解释，追加修正及原因。
6. 用本轮证据更新当前 Spec 测试文档；未运行项目逐项保留并写明原因。只有跨 Spec 结论、项目风险状态或项目覆盖判断改变时才更新 TCO。

## 写回当前 Spec

只更新与本轮执行有关的内容：

```markdown
## 当前测试轮次
- 实际执行范围、排除项、环境、执行人和访问方式

## 执行证据
- <测试 ID／charter ID>：已运行测试／Probe — 原始观察 — 证据链接
- <测试 ID／charter ID>：Finding — 影响 — 当前可信度
- <测试 ID／charter ID>：未执行内容 — 原因

## 产品风险
- <风险 ID>：被本轮证据提高、降低或新增的风险 — 关联测试／charter ID — 依据

## 下一步
- 下一项测试、待确认问题或停止理由 — 触发条件
```

观察只陈述实际看到或收到的原始结果；解释、影响和可信度另列。原始证据过长时放入独立文件，当前 Spec 测试文档保留摘要、稳定 ID 和相对链接。未执行计划不能升级成项目证据。

**完成条件：** 当前 Spec 明确实际执行了哪些测试、由谁执行、观察到什么、证据在哪里、哪些未执行及原因；每条结果和 finding 可追溯到测试 ID 或 charter ID；局部证据留在 Spec，TCO 只接收符合升级判据的变化；产品风险和下一步由本轮证据更新，计划没有冒充结果。
