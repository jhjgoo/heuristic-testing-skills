# 澄清测试依据

当前协作者通常是测试人员。与其共同补齐产品认知，不让他替产品、业务、研发或发布负责人制定规则。

## 上下文契约

接收调用方给出的材料、业务与系统上下文及已有未知。首次共同探索尚未收到回答时，不创建或扩写完整测试文档。返回事实、假设、未知、oracle 和测试变化；调用方决定写入对话、Spec 或 TCO。不另建澄清报告。

## 探索循环

1. **调查：** 汇总 PRD、业务规则、原型、接口契约、架构、代码、配置、数据、日志、历史缺陷、人员说明、TCO 和当前 Spec 测试文档。能自行取得的事实先调查并留下证据。
2. **建模：** 先写出当前事实、推断、假设、未知及来源。确定用户任务、现状痛点、产品承诺和成功信号，再把需求放回真实业务链与系统联动。
3. **生问：** 读取 `references/guideword-cards.md`，让当前最相关的少数引导词碰撞具体对象，生成候选问题。
4. **选问：** 每轮只解决一个探索目标。业务规则、实体关系、状态或计数口径等概念歧义，默认只问一个问题；多个问题只有在彼此独立、答案不会互相改变含义时才同轮提出。问题必须由当前协作者能够回答，并可能改变测试使命、产品模型、质量判断、oracle、测试重点或下一步。
5. **反馈：** 收到回答后先展示认知变化。每个答案必须落到事实、推断、规则、测试输入、假设或未知，并新增、删除、拆分、合并、改序或延后具体测试工作。
6. **转向：** 问不到时转为信息收集任务、可推翻假设或测试实验。剩余未知不再改变当前选择时，停止提问并开始有界测试；新证据改变模型或选择时重入本循环。

概念问题先给一个具体业务例子或时间序列，再让用户确认或修正；不用未确认的领域模型组织问题。用户表示没看懂或指出理解错误时，立即撤回错误假设，用用户语言重述当前模型，只重问被误解的问题并等待；不要追加新的问题前沿。业务语义稳定后，再单独收集业务链、系统关系和证据源。

只展开当前请求受影响的问题前沿。问题前沿记录依赖、应答角色和测试影响；它用于选择下一问，不要求清空。材料中已有答案、Agent 可自行调查，或答案不会改变当前测试的问题，不打断用户。

从用户动词推断测试目的和交付物。普通“测试分析”直接理解为共同建立上下文、候选测试点和下一步；不询问 PRD 是否可研发、MVP 是否可联调或产品是否可上线。只有用户明确请求准入、放行、停止或风险接受时，才确认对应决定和负责人。

## 证据与权限

记录答案时区分：

- **已知事实：** 材料、系统或观察可以证明；
- **推断：** 由现有事实推演，尚未经证据或负责人确认；
- **已确认规则：** 有权负责人明确确认；
- **测试输入：** 测试人员提供的经验、现象或历史信息；
- **暂定测试假设：** 为继续分析暂时采用，不能充当 oracle；
- **未知：** 仍需调查或交给对应负责人确认。

用户提出处理办法但其决策权限不明时，只记为暂定测试假设。暂定假设可以支持有限分析，不能充当产品规则或 oracle。

优先索取真实流程、具体例子、反例、历史观察和可访问证据。产品／业务负责人确认规则；研发／系统负责人确认实现边界；运维／安全／发布负责人确认相应约束。当前测试人员提供测试经验、观察和证据，不替其他角色作决定。

## 输出

首轮提问：

```markdown
## 当前理解
- 事实／推断／假设／未知 — 来源

## 本轮探索
- 目标：<本轮只解决什么>
- 当前依据：<为什么现在问>
- 问题：<默认一个具体问题；独立事实查询才允许 2～3 个>
- 测试影响：<答案会改变什么>
```

收到回答后：

```markdown
## 当前理解
- 事实／推断／假设／未知 — 来源

## 本轮认知变化
- 新事实：<没有则写“无”>
- 被修正的假设：<没有则写“无”>
- 模型变化：<业务链、系统边界、数据、质量或 oracle>
- 测试变化：<关联稳定 ID 或具体下一动作>

## 下一轮
- 继续探索：<一个目标；问题按“选问”规则组织>
- 或开始测试：<有界动作与依据>

## 未决项
- 待取证／待确认／暂定假设 — 来源或负责人 — 测试影响

## 交给调用方
- 本轮认知变化：<事实、假设、未知或 oracle>
- 测试变化：<新增、删除、拆分、合并、改序或延后>
- 下一步：<立即行动>
```

首轮尚未收到答案时，不输出空的“本轮认知变化”。收到答案后，“模型变化”和“测试变化”不得同时为空。

首次共同探索的回复只输出“当前理解”和“本轮探索”，然后等待回答。当前理解保持在支撑本轮问题所需的最小范围；不提前输出完整测试文档、当前测试重点、产品风险、候选测试点或测试计划。

**完成条件：** 当前探索目标已有足以选择下一测试动作的信息，或未知已转为明确取证／实验任务；用户可以直接确认或修正当前具体例子；每个答案只对应一个模型决策及明确测试变化；没有把测试人员输入升级为越权产品规则。问题前沿无需清空。
